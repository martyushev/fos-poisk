## Назначение ФОС

Фонд оценочных средств предназначен для оценки уровня сформированности профессиональных компетенций обучающихся в области применения нейросетевых методов и архитектур глубокого обучения в информационном поиске, включая трансформерные модели, эмбеддинги, семантический поиск и вопросно-ответные системы.

В рамках модуля оценивается способность обучающегося:

- понимать архитектуру Transformer, механизм Self-Attention и принципы работы multi-head attention;
- различать contextual embeddings (BERT) и static embeddings (Word2Vec, GloVe);
- объяснять принципы работы Bi-Encoder и Cross-Encoder архитектур и их применение в ранжировании;
- использовать CLS-токен для получения векторных представлений документов;
- реализовывать пайплайны семантического поиска с использованием Bi-Encoder и Cross-Encoder;
- применять методы понимания запроса: исправление опечаток, выделение сущностей, классификацию интентов, расширение запроса;
- использовать генеративные модели (T5, BART, GPT) для переформулирования запросов;
- оценивать качество поисковых систем с использованием метрик Recall, MRR, NDCG;
- проектировать гибридные архитектуры поисковых систем;
- понимать проблемы domain adaptation и fine-tuning поисковых моделей.

# Лабораторная работа №4.3. Query Understanding Pipeline

**Продолжительность:** 3 академических часа

**Цель работы:** Изучить принципы построения конвейера (pipeline) предобработки и понимания поискового запроса, а также оценить влияние каждого этапа на качество конечного поиска.

## Описание задачи

Вам предстоит реализовать конвейер обработки пользовательского запроса, состоящий из трех последовательных модулей, и оценить их совместное влияние на ранжирование результатов поиска.

### Исходные данные

- **Корпус документов:** Набор текстовых документов (например, новостные статьи, описания товаров или научные рефераты). Вы можете использовать встроенный датасет `sklearn.datasets.fetch_20newsgroups` для тестирования.
- **Тестовые запросы:** Список из 50–100 пользовательских запросов, для которых вручную размечены релевантные документы (бинарная релевантность: 1 — релевантен, 0 — не релевантен).

## Этапы выполнения

### 1. Исправление опечаток (Spell Correction)

**Цель:** Обработать орфографические ошибки в запросе.

- **Реализация:** Используйте библиотеку `symspellpy` (алгоритм SymSpell) или предобученную модель типа `T5-small` для исправления опечаток (доступна на Hugging Face).
- **Вход:** Текст запроса с возможными ошибками.
- **Выход:** Исправленный текст запроса.

### 2. Классификация интента (Intent Classification)

**Цель:** Определить категорию намерения пользователя для последующей настройки поиска.

- **Классы интентов (на выбор):**
  - `NAVIGATION` — поиск конкретного сайта или страницы.
  - `INFORMATION` — поиск фактов или знаний.
  - `TRANSACTION` — коммерческие запросы (покупка, цена).
  - `TROUBLESHOOTING` — проблемы и их решения.
  - `ENTERTAINMENT` — развлекательный контент.
  - `SOCIAL` — социальные сети и общение.
  
- **Реализация:** Возьмите предобученную модель `bert-base-uncased` и дообучите (fine-tune) ее на синтетическом датасете (см. раздел "Источники данных").

### 3. Расширение запроса (Query Expansion)

**Цель:** Обогатить запрос синонимами и связанными терминами для повышения полноты поиска.

- **Вариант реализации (на выбор):**
  - **MLM:** Использовать маскированную языковую модель BERT для генерации слов на место `[MASK]` (например, запрос "купить [MASK] телефон" → "купить новый телефон").
  - **Модель генерации:** Использовать `doc2query` (T5-based) для генерации возможных запросов по тексту документа.
- **Выход:** Исходный запрос + 3-5 сгенерированных терминов/фраз.

### 4. Интеграция в единый конвейер (Pipeline)

Соберите три модуля в последовательную цепочку:  
`Запрос (сырой)` → `Spell Correction` → `Intent Classification` → `Query Expansion` → `Поиск (ранжирование)`.

## Оценка качества (Ablation Study)

Для измерения эффективности вашего пайплайна используется метрика **nDCG@10** (Normalized Discounted Cumulative Gain).

### Процедура оценки

1. Для каждого тестового запроса выполните поиск по вашему корпусу с использованием:
   - Базового поиска (только лемматизация/токенизация).
   - Только Spell Correction.
   - Только Intent Classification (используйте класс для взвешивания полей при поиске).
   - Только Query Expansion.
   - Полного пайплайна (все три модуля).

2. Рассчитайте nDCG@10 для каждого варианта.

3. Постройте итоговую таблицу:

|------------------------|---------|
| Базовый поиск          | 0.45    |
| + Spell Correction     | 0.52    |
